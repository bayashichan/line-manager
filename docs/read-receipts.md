# 既読表示と1:1チャットへの集約

## 結論（先に制約）

LINE Messaging API には **既読を知る手段が存在しない**。

- 既読を通知する Webhook イベントは無い
- 送信済みメッセージの既読状態を取得する API も無い
- LINE公式アカウントアプリ（純正アプリ）のチャットで**オペレーターが送ったメッセージ**を
  取得する API も無い

そのため「LINEのトーク画面と同じ既読」は原理的に実装できない。
本システムでは実務で使える形として **みなし既読（推定既読）** を採用している。

## みなし既読の判定ルール

友だち自身の操作を「トークを開いた証跡」として扱い、その時刻より前に
こちらから送ったメッセージを既読にする。

| 根拠 (`read_source`) | 検出元 | 意味 |
| --- | --- | --- |
| `message` | Webhook の message イベント | 友だちが返信した |
| `postback` | Webhook の postback イベント | ボタン・リッチメニューをタップした |
| `link_click` | `/api/actions/redirect` | 配信に入れたリンクをタップした |
| `other` | videoPlayComplete など | 配信した動画を最後まで再生した など |

判定は `src/lib/chat/read-receipts.ts` の `markFriendReadUpTo()` に集約している。

設計上の約束:

- 既読時刻は**イベント発生時刻**（`event.timestamp`）を使う。処理時刻を使うと
  Webhook の遅延ぶんだけ既読の境界がずれる
- 根拠にするのは**友だち自身の操作だけ**。管理側の操作（配信・タグ付け）では既読にしない
- 一度付いた既読は上書きしない（`read_at IS NULL` の行だけ更新する）
- 既読処理が失敗しても Webhook の主処理は止めない（既読は補助情報）

### 「未読」の意味

画面では `未確認` と表示している。**読んでいないという意味ではなく、
反応がまだ確認できていない**状態を指す。実際には読んでいても、返信もタップもしなければ
未確認のままになる。この前提を画面上にも注記している。

## 友だちごとの既読状況（一斉配信）

配信直後に `message_recipients` へ友だち単位の行を作る。

- 記録場所: `src/lib/messaging/delivery-log.ts` の `recordBroadcastDelivery()`
- 呼び出し元: `/api/messages/send`、`/api/cron/scheduled-messages`、`/api/webhook/qstash-line`
- マルチキャストは相手ごとの結果を返さないため、**バッチ単位の成否を全員に割り当てる**
- 失敗した相手には `sent_at` を入れない（「送ったのに未読」に見えてしまうため）

閲覧は配信履歴カードを展開すると出る「既読状況」（`src/components/delivery-read-status.tsx`）。
API は `GET /api/messages/[id]/recipients?status=all|read|unread|failed`。

この機能より前の配信には対象者の行が無いため、「記録がありません」と表示される。
遡って作ると誰に届いたか分からないまま行だけ増えるので、あえて埋めていない。

## 1:1チャットへの集約

トーク画面を実際のLINEに近づけるため、**本システム経由の送信はすべて `chat_messages` に残す**。
`delivery_source` でどの経路かを判別する。

| `delivery_source` | 経路 |
| --- | --- |
| `chat` | チャット画面からの手動送信 |
| `broadcast` | 一斉配信・予約配信 |
| `step` | ステップ配信 |
| `auto_reply` | キーワード自動応答 |
| `line` | 友だちからの受信 |

### 受信メッセージの実体取得

Webhook には画像・動画・音声・ファイルの実体が入っておらず `messageId` しか来ない。
`src/lib/chat/incoming.ts` で LINE のコンテンツ API から取得して R2 に保存し、
表示可能な URL を `content` に埋めている。これをやらないと、公式アプリでは見えている
やり取りが管理画面では空の吹き出しになる。

スタンプは公開CDNのURLを組み立てるだけで実体保存は不要。位置情報は緯度経度を保持して
地図リンクにする。送信取消（`unsend` イベント）は本文を消して「送信が取り消されました」に変える。

コンテンツの取得期間は LINE 側で限られているため、**Webhook 受信時にその場で保存する**。
ただし Webhook の応答を長時間ブロックすると LINE 側が失敗とみなすため、取得には
8秒のタイムアウトと 20MB のサイズ上限を設けている。上限を超えた場合はメディアを諦め、
テキストのみのフォールバック表示にする（吹き出し自体は残る）。

### 一斉配信は友だちリストを押し上げない

一斉配信では `line_users.last_message_at` を更新していない。全員を先頭に押し上げると
返信待ちの相手が埋もれて実務で使えなくなるため。トーク履歴には並ぶが、一覧の並び順は変わらない。

### 大規模配信での打ち切り

1:1チャットへの複製は「友だち数 × メッセージブロック数」だけ行が増える。
`MAX_THREAD_SYNC_ROWS`（20,000行）を超える配信では複製をスキップし、
既読集計に必要な `message_recipients` の記録だけ残す（ログに警告を出す）。

## 実装できないこと

**LINE公式アカウントアプリからオペレーターが送ったメッセージは、1:1チャットに表示できない。**
LINE がそれを取得する API を提供していないため。

対処としては、送信の窓口を本システムのチャット画面に寄せると履歴が揃う。
なお、友だちから届いたメッセージは公式アプリで対応した場合でも Webhook 経由で
本システムに残るので、受信側は欠けない。
